# 授权包 (license_pkg) — 离线授权 / 期限控制工具

本包与 **部署包 (ftp_puller_pkg)** 是分开的两份。  
**部署包**发到客户/目标机上运行（它只带"校验器"，带不动"造钥匙"的能力）；  
**本授权包**由你自己保管，用来**生成授权文件**和**换锁**，不让别人拿到生成器。

## 包含的组件
- `index.html`      —— **授权生成器（核心工具）**：浏览器打开即可生成 / 校验 `license.dat`，纯前端、不联网、密钥内嵌
- `license_core.py`  —— 与部署包**完全相同**的授权核心（本包用它来"签名"，部署包用它来"验签"；两者密钥一致才能对得上；也方便你在 Linux 上脚本化出钥匙）
- `LICENSE.md`      —— 本说明

> 编译成二进制（`build_linux.sh`）放在**部署包**里，因为它编译的是部署包自己的源码。  
> 本包只负责"出钥匙"。

## 一、生成授权文件（两种方式，任选）

### 方式 A：网页工具（推荐，最省事）
直接用浏览器打开本包的 `index.html`（双击即可，无需联网、无需安装）：
1. 填**到期日期**（必填），签发日期可留空（默认今天）；
2. 点「生成 license.dat」→ 内容出现在文本框；
3. 点「下载 license.dat」把文件存下来，或「复制文本」手动存成 `license.dat`。

> ⚠️ `index.html` 内含授权密钥，请妥善保管、不要外发给客户。

### 方式 B：命令行（Linux 上脚本化）
```bash
# 生成到期日为 2027-12-31 的授权
python3 license_core.py make 2027-12-31            # 直接打印到屏幕
python3 license_core.py make 2027-12-31 --issued 2026-10-11 > license.dat
```
（`license_core.py` 末尾加了 CLI：`--make 到期日 [--issued 签发日]` / `--check license.dat`）

把生成的 `license.dat` 放到运行机的 `/opt/ftp_puller/license.dat`（或与二进制同目录）即可。

## 二、授权逻辑（只做两件事，与机器码/业务无关）
1. **签名校验**：HMAC-SHA256 防篡改，文件被改过立即失败。
2. **使用期限**：比对 `expire` 与今天，超过到期日即失效。

> 不做机器码绑定、不联网、不依赖任何业务路径。要更严格（绑定机器、限台数）可后续在
> `license_core.py` 里扩展，但当前按需求保持最简。

## 三、授权失效在运行端的表现
运行机日志首行出现 `[LICENSE-FAIL] ...`，例如：
- `未找到授权文件: ...` —— 没放 license.dat
- `授权已过期 (到期 2026-10-01, 今天 2026-10-11)` —— 到期了，需用本包重新生成
- `授权文件签名校验失败(可能被篡改)` —— 文件被改过
程序 `exit(1)`，systemd 会反复拉起但持续失败（这是预期的保护行为）。

## 四、换锁（让旧授权全部失效）
改 `license_core.py` 里的 `AUTH_KEY` 常量 **（部署包和本包的 `license_core.py` 必须同时改、改成一样的值；同时 `index.html` 里 `AUTH_KEY_STR` 也必须改成相同值）**，
然后用本包重新生成 license、用部署包的 `build_linux.sh` 重新编译即可。
